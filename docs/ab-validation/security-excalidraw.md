# A/B валідація: `security-excalidraw.mdc`

## 1. Яке правило тестувалось

- Файл: `.cursor/rules/security-excalidraw.mdc`
- Тема: безпека в контексті Excalidraw (XSS, імпорти, CSP, шифрування колабу, Firebase), з прив’язкою до конкретних шарів репозиторію замість загальних порад.

## 2. Тестовий сценарій (промпт для AI)

> Ти в монорепо Excalidraw. Треба додати прев’ю для елементів імпортованої бібліотеки: SVG з JSON бібліотеки показати в мініатюрі в UI. Запропонуй зміни в коді та що врахувати з точки зору безпеки.

(Промпт однаковий у обох прогонах; різниця лише в тому, чи підключене правило `security-excalidraw.mdc` у контексті Cursor.)

## 3. Результат A (без правила `security-excalidraw.mdc`)

- Поради зводяться до загальних формулювань: «санітизуй HTML», «використай DOMPurify», «не довіряй користувацькому вводу».
- Немає згадки про те, що JSON бібліотеки та SVG-прев’ю в Excalidraw — **вже відомий ризиковий шлях** у продукті, і що важливо **не відкривати новий «сирий рядок → DOM»**, якщо вже є прийняті патерни в коді бібліотеки.
- CSP, `excalidraw-app/index.html`, Vite і відмінність dev/production **не згадуються**, хоча зміни можуть торкнутися завантаження скриптів або inline-розмітки в оболонці застосунку.
- Шифрування колабу (`encryptData` / `decryptData`, Collab) і Firebase **не прив’язуються** до файлів репозиторію — лише загальне «не логуй секрети».

## 4. Результат B (з правилом `security-excalidraw.mdc`)

- Явно сказано, що **вставка SVG у DOM** для прев’ю бібліотеки — високоризикова; краще шукати **існуючі** підходи в `packages/excalidraw` (керований рендер прев’ю), ніж новий шлях «рядок з бібліотеки → `innerHTML`».
- Згадано **імпорт недовірених даних**: JSON бібліотеки від користувача; наголос на валідації/restore в `packages/excalidraw/data/` замість ad-hoc парсингу в UI.
- Якщо зміни зачіпають оболонку або нові origin/inline-скрипти — нагадування про **CSP** і те, що в dev може «просто працювати», а в production — ні (`excalidraw-app`, Vite, `index.html`).
- Для змін у crypto/collab — орієнтири на `packages/excalidraw/data/encryption.ts` та `excalidraw-app/collab/Collab.tsx` (без логування ключів/plaintext).
- У блоці перевірки згадані **реальні команди** репозиторію: `yarn test:typecheck`, `yarn test:code`, `yarn test` / `yarn test:app`, ручна перевірка імпорту та за потреби колабу.

## 5. Висновок

- **Різниця:** без правила відповідь виглядає «правильно» загалом, але **не прив’язана до Excalidraw** (шляхи файлів, відомі вектори в цьому репо, CSP/імпорт/прев’ю бібліотеки).
- **З правилом** з’являються **конкретні зони коду й процес перевірки**, що відповідають змісту `.cursor/rules/security-excalidraw.mdc`.
- **Висновок для практики:** правило зменшує ризик загальних порад і змушує тримати security-обговорення в рамках реального монорепо, тому його варто лишати в `.cursor/rules/` для змін у `packages/excalidraw` та `excalidraw-app`.
